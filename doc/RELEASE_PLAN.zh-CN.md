# Stalltrace 首版开源规划

建议将 Stalltrace 定位为可嵌入 Flutter 应用的 Android 前台卡顿诊断插件。首版交付标准是，接入方能在自己的 release 包中，从一次系统确认的输入 ANR 追到对应的 Dart 或 Native 源码行，并看清这次归因的依据。发布日期以真机和兼容性验收结果为准。

## 项目状态

`lib/stalltrace.dart` 提供 `Stalltrace.start()`、`Stalltrace.stop()` 和能力返回值。Android 插件监听宿主 Activity 生命周期，复用进程级采样器，后台写入主线程样本，并在 API 30+ 导入本进程可用的历史 trace。`tool/symbolize.py` 校验 Build ID 并独立解析两种来源。`example/` 作为普通 path 依赖接入，阻塞注入和手工导出位于独立的 `tool/anr_lab/` 验收工程。

原型阶段在 API 37 模拟器上确认了四次输入 ANR。2026-11-25 对独立插件重新运行三个用例，使用 Flutter 3.47.9 的 ARM64 release 示例、无 Dart 混淆。以下数据仅来自插件复验。

| 用例 | 系统 ANR 事件数 | 命中预设函数的现场样本 | 系统 trace |
| --- | ---: | ---: | --- |
| 18 秒 Dart 计算 | 1 | 9/9，最近样本距系统事件 622 ms | 独立还原到 Dart 计算函数及其调用者 |
| 18 秒同步 FFI 等待，7 秒后注入输入 | 1 | 9/9，最近样本距系统事件 318 ms | 独立还原到 C 等待函数、C 入口和 Dart 调用者 |
| 2.3 秒短卡顿 | 0 | 1/1 | 阻塞期间无系统 ANR 事件 |

静态检查、两个 Dart 接口测试、一个示例页面测试及干净源码构建均已通过。示例与验收命令见 [复现说明](../tool/anr_lab/README.md)。完整原始设备输出仅保存在本地。模拟器上的两个正例尚不足以估算线上召回率。

### 开源后新增的候选版验证

2026-11-25，本机使用 API 29、API 37 两个 ARM64 模拟器运行混淆 release 示例。每个系统分别执行 Dart 计算、同步 FFI、纯 Android JNI 三种输入 ANR，以及 2.3 秒短卡顿对照。六次长阻塞均取得同 PID 的系统事件并命中预设函数。两次短卡顿均未产生系统 ANR。纯 JNI 用例校验现场采样的完整帧列表中没有 `libapp.so`。API 37 另外以系统 trace 独立还原，API 29 按系统能力只验现场栈和实验事件。模拟器数据单独统计。

在最终的混淆 release 包上，API 29 的三个正例分别命中 9/9、8/8、8/8 份现场样本，API 37 分别为 9/9、9/9、8/8。两台模拟器上另外各执行一次阻塞中途强停，重启后均从未写入恢复标记的文件中解出了此前的 Dart 业务栈。API 37 上还验证了同一进程切后台、返回前台和横竖屏切换，暂停采样期间的短卡顿记录为 0，恢复采样后的短卡顿记录为 1。

API 37 设备集成测试还覆盖已占用的采样信号、重复启停、Java 采样降级，以及用 Dart API 枚举和删除一条报告。Android 单测覆盖旧格式、分段报告、活动报告保护、删除中断恢复，以及历史记录重新导入时保持删除状态。[设备复现步骤](../tool/anr_lab/README.md) · [GitHub CI](https://github.com/arkin1614-code/stalltrace/actions/workflows/ci.yml)

### 评审后的候选版 `0.1.0-dev.3`

现场采样先持久化原始 PC、返回地址、采集时间及内核映射，再从映射对应的 ELF 解析 Build ID。采样路径绕开 Android 动态链接器锁。模块未能核实时保留原始记录。报告按完整卡顿分组清理，启动时也执行保留配额。

Dart 接口通过 `traceAssociation` 返回关联状态。主进程段的 PID、进程名和 dump 时间必须匹配现场卡顿，且双方都只有一个候选。匹配结果给出退出报告 ID、选中样本的单调时钟时间戳及相对 dump 的有符号毫秒差。已恢复的 ANR 可以关联至后续其他原因的退出记录。旧格式现场记录缺少进程名时保留为未关联。

模拟器和真机使用同一个验收脚本。API 24–29 从设备读取实际可用的 libc。换栈用例先做 11 秒 Dart 计算，再做 13 秒同步 FFI，分别在两阶段注入输入。验收比对事件附近的函数、源码文件和行号，检查同进程短卡顿的关联状态，并逐个检查纯 JNI 样本。慢加载用例在动态库构造函数中途强停，重启后要求首段及轮转段均能解出构造函数。[验收脚本及运行命令](../tool/anr_lab/README.md)

2026-11-25 的 `dev.3` 混淆 release 在 API 28 和 API 37 ARM64 模拟器上各取得 5 次系统输入 ANR。每台长阻塞合计 46/46 份样本命中对应阶段的函数与源码范围，两次短卡顿均无系统 ANR。API 37 的 5 个正例各自关联到唯一的系统 dump，同进程短卡顿保持未关联。5 个选中样本相对 dump 的有符号时间差为 −79 至 +942 ms。API 28 通过旧版 libc 路径独立解码。两台模拟器均在 Dart 阻塞强停后恢复现场，并在慢加载强停后从首段及轮转段解出构造函数。真机数据单独统计。

### 首台真机发现的换栈边界 `0.1.0-dev.4`

一台 Android 17 ARM64 商用设备的输入超时为 10 秒。开发版 `dev.3` 实测出现过一次阶段错配：系统在 Dart 计算期间抓栈，721 ms 后的最近现场样本已进入同步 FFI。该轮保留为失败。用 `dev.4` 回放同一份原始记录，两处连续的调用地址和叶子模块 Build ID 与系统栈一致，选中了提前 1,369 ms 的 Dart 样本。Dart 接口通过 `sampleSelection` 说明使用了帧证据或仅有时间邻近性。时间差始终相对于系统 dump。

真机验收采用同一混淆 release 构建，换栈前后各阻塞 18 秒。脚本记录二次输入的设备时间，核对系统实际等待时长和输入类型，按需关闭该示例的 ANR 对话框，再启动下一用例。性能对照在同一进程、同一 APK 内进行，暂停和启用采样分别静置 10 分钟。[复现说明](../tool/anr_lab/README.md)

三星 SM-F9660（Android 17，API 37，ARM64）完成五轮前台堆栈验收。以下数字来自同一份混淆 release APK。五种正例各取得 5 次系统输入 ANR、5 份可独立解码的系统 trace 和 5 次唯一关联。25 次样本选择均有帧证据，所选样本相对系统 dump 的有符号时间差为 −1,010 至 +833 ms。各事件最近的命中样本距系统事件 10 至 930 ms。

| 用例 | 系统输入 ANR | 命中函数和源码范围的样本 |
| --- | ---: | ---: |
| Dart 计算 | 5 | 40/40 |
| 同步 FFI | 5 | 42/42 |
| 纯 JNI | 5 | 43/43，含应用 Dart 帧的样本为 0 |
| 换栈前注入输入 | 5 | 85/85 |
| 换栈后注入输入 | 5 | 85/85 |
| 2.3 秒短卡顿 | 0 | 5/5，系统 trace 关联为 0 |

五轮均在 Dart 阻塞强停后找回带符号的现场栈，并从慢加载强停前的首段及轮转段找回构造函数。一轮中途发生过额外的失焦事件，系统以后台 ANR 终止进程。该事件单独记录，系统 trace 命中 FFI，重启后读到 14 份现场样本，其中 6 份含同步 Dart/Native 调用链。前台用例重新执行后按上表统计。第 2 至 5 轮导出时都达到 24 组卡顿、12 组退出报告的保留上限，五次导出均未发现缺少首段的轮转文件。

另在同一进程验证了暂停、切后台、返回前台、横竖屏切换以及重新启用采样。暂停时触发的 2.3 秒短卡顿留下 0 份样本，恢复后重复触发留下 1 份样本。测试结束后已核对手机原有的旋转设置。

### 第二台真机与致死 ANR 的最后一个采样间隔

一加 PGP110（Android 15，API 35，ARM64）安装的 `dev.4` 混淆 release APK 与三星逐字节相同。五轮共取得 25 次前台输入 ANR，系统均在输入等待约 5 秒后记录超时，随后结束该进程。重启后，25 份系统 trace 和对应的现场文件均可读取。每次均核对前台进程、同一次输入超时的终止原因、进程死亡时间以及独立解码的系统主线程栈。

| 一加用例 | 系统输入 ANR | 命中源码范围的现场样本 | `dev.4` 直接关联 | `dev.5` 回放同一批记录 |
| --- | ---: | ---: | ---: | ---: |
| Dart 计算 | 5 | 15/15 | 5/5 | 5/5 |
| 同步 FFI | 5 | 15/15 | 0/5 | 5/5 |
| 纯 JNI | 5 | 13/13 | 3/5 | 5/5 |
| 换栈前注入输入 | 5 | 15/15 | 5/5 | 5/5 |
| 换栈后注入输入 | 5 | 57/57 | 2/5 | 5/5 |
| 2.3 秒短卡顿 | 0 | 5/5 | 0 次关联 | 0 次关联 |

10 次遗漏均发生在系统 dump 晚于最后一份落盘样本时，二者相差 331 至 1,444 ms。`dev.5` 只对系统标记为 ANR 退出且仍未结束的最后一个探测检查这个间隔。样本到 dump、dump 到退出分别须在 2.5 秒内，叶子模块 Build ID 及两个连续调用地址须与系统栈一致。复用原始数据回放，修复后的一加 25 次及三星 25 次均有帧证据。三星的回放使用此前的真机记录。

首轮同步 FFI 的系统栈和现场样本均定位到同一条调用链。Dart 的 `fixtureDartFfiCaller`（`lib/main.dart:33`）调用 C 的 `fixture_native_entry`（`fixtures.c:11`），再进入 `fixture_native_wait`（`fixtures.c:8`）。系统栈还能看到调用进入 libc 的 `nanosleep`。

一加的五次提前注入均在 Dart 阶段被终止，因此只验证了实际执行的 Dart 阶段。五次延后注入均先观测到 Dart，再观测到同步 FFI；系统事件对应 FFI。纯 JNI 的 13 份样本中，应用 Dart 帧为 0。五轮均通过 Dart 阻塞强停恢复与慢加载首段、轮转段恢复。调整验收脚本前还额外记录了一次真实 Dart ANR，重启后找回 3/3 份 Dart 样本，单独保留，不计入上表。

## 发布前值得盯住的三个失败场景

- **系统 trace 缺失或抓晚。** 保留现场样本、时钟和来源。关联缺少唯一证据时保留“不确定”，把可确认与不可确认事件分开统计。
- **宿主已有采样 SDK，或库缺少可展开帧。** 验证信号共存、超时、截断及降级行为。验收要包含一个纯 Native 阻塞，确保没有 Dart 业务帧时不会补出伪帧。
- **公开材料泄露现场信息。** 检查发布归档、CI 日志和 issue 模板。公开复现只用示例或经过检查的摘要；原始生产 trace、符号和签名材料由接入方保存。

M0 已完成，公开源码使用 MIT。M1 的双机堆栈矩阵已通过，同一份 `dev.5` APK 在三星 Android 17 和一加 Android 15 上分别直接执行五轮。现有结果适用于本文的 ARM64 混淆 release、平台线程与 root isolate 合并、前台输入 ANR 场景。pub.dev 正式发布待维护者评审确认。
